Case Loan Selector for Agents

Replacing manual Product ID entry with a guided, multi-loan picker on Case records

Fewer invalid Product IDs
Faster case intake

Problem Statement

  • 1 Agents type loan IDs by hand. Product_ID__c is a free-text field. Agents copy ARIs from Agent Portal or customer statements — typos, wrong format, and invalid IDs are common. Validation rules reject bad formats after the agent has already moved on.
  • 2 Multiple loans require multiple fields. One case can involve several loans. Today that means Product_ID__c plus semicolon-delimited Additional_Product_Ids__c, or separate fields like Disputed_Product_ID_s__c. No structured merchant or status per loan.
  • 3 Customers pick loans in self-service — agents don't. Experience Cloud uses loan-level servicing (Get_User_Loans API). Agents re-type what the customer already selected in chat or webforms.
  • 4 Downstream data is thin. Reports and Agent Portal links only see a raw ARI string. Merchant_name__c and Status_of_Loan__c hold one loan at most and are often blank.
"An agent handling a merchant dispute with three active loans has to look up each ARI in Agent Portal, type them into separate Case fields, and hope the format passes validation — with no merchant name or loan status stored unless they fill that in too. Customers on the same platform pick loans from a list in under 10 seconds."

Proposed — Case Loan Selector

A
Fetch customer loans Reuse Get_User_Loans integration (same API as help center). Resolve User ARI from Case → Contact → Account.
B
Multi-select with context Searchable list: merchant, ARI, status, product type, servicer — no dollar amounts.
C
Structured storage New Case_Loan__c child records per loan. One marked Primary for Agent Portal deep link.
D
Manual fallback If User ARI is missing or API fails, agent can enter an ARI manually (validated format).

Data & Compliance

What we store — and what we don't

For ops and compliance reviewers. Salesforce is not authorized to hold customer financial information.

Stored on Case_Loan__c

  • Loan / Product ARI
  • Merchant name
  • Loan status
  • Merchant product type & platform
  • Servicer
  • Record type (Loan vs Application)
  • Primary flag (one per Case)

Never persisted

  • Payment amounts or balances
  • Due dates or overdue amounts
  • Autopay or collection flags
  • Phone numbers or user labels
  • Any PCI, PII, or financial data

The Get_User_Loans API may return financial fields for help-center display. The agent picker strips them at the Apex boundary before any UI render or DML. Phase 1: US Affirm cases only.
